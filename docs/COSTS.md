## 为什么调用量比单份报告大

实际执行了 54 次合成对照，以及 smoke、数据证据、两版语义复核、最终验收和多版公开题运行；不能只看最后一份 2 题或 4 题报告。公开题 v1 单轮已累计 1,672,068 Tokens；后续改进与同题重测继续产生新的调用。输入统计还包含每轮重新发送的历史上下文，并非唯一文本量。任务运行中 5,905,528 个输入 Tokens 命中缓存，不能全部按未命中单价当作实际费用。

846 个任务响应与 2 个探针响应的缓存字段均齐全；逐次输入＋输出、命中＋未命中、每条运行保存的调用数与 usage 均对得上。任务与探针原保存估算合计为 2.256506 USD，与精确重算差 0.000005 USD，来自逐次／逐运行取整。原估算没有使用真实缓存折扣与空闲价格，应继续标为保守估算。

- `refund-verified-01` 的 case 目录仍在，但当前 `external/native-results` 没有对应 agent JSON／JSONL。仅有环境准备不能证明发生过几次模型调用；该项记为 usage 缺失，不写成零费用。
- 早期 Flash 小探针尚未找到原始 usage，未凭回忆补金额；Pro 工具调用兼容探针已找到原始两条 usage，已计入扩大后的 848 次响应，不能继续称为完全缺失。另有 `account_availability_20261025.json`，只记录 HTTP200／可用状态的只读诊断，不是生成调用。
- 四题各有一次 HTTP402 中断。错误响应没有 usage；超时、服务端重试、进程在保存前结束也可能留下缺口。已返回并保存的响应照计，没有返回的用量不猜、不强记为零。
- 未读取平台账单、期初余额、充值流水或该 Key 在项目以外的用量。因此当前重估不能与余额差直接对账，尤其不能声称“实际只扣了 1.53 元”。实际扣费应以平台逐条用量与账单为准。
